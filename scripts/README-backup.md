# Резервные копии базы

Копии лежат на компьютере владельца в `~/ShopTourBackups/<дата>/`, хранятся последние 30.
В них личные данные покупателей и магазинов — папку не выкладывать и не отправлять.

## Что в копии

- `public.sql.gz` — все таблицы сайта: структура, правила доступа (RLS), данные.
- `auth-users.sql.gz` — аккаунты (покупатели, владельцы магазинов, сотрудники), только данные.
- `storage-list.sql.gz` — список загруженных фото. Самих файлов в копии нет — они в хранилище Supabase.

## Расписание

`~/Library/LaunchAgents/kz.shoptour.backup.plist` запускает `scripts/backup-db.sh` каждый день в 13:00
и при входе в систему; вторая копия за тот же день не делается. Журнал — `~/ShopTourBackups/backup.log`.

Вручную: `./scripts/backup-db.sh` (или `--force`, чтобы переснять сегодняшнюю).

## Восстановление

В пустой проект Supabase, по порядку (`$DB` — строка подключения нового проекта):

```sh
gunzip -c auth-users.sql.gz | psql "$DB"
gunzip -c public.sql.gz | psql "$DB"
```

В существующей базе таблицы уже есть, поэтому нужные данные достают из файла выборочно.
